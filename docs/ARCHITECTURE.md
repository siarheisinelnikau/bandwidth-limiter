# Architecture

`model.rs` owns settings, validation, executable-path identity and weekly schedules. `policy.rs` is deterministic: callers inject monotonic time, local date, weekday and minute. Each application/direction has one shared token bucket, a maximum quarter-second burst, and a zero-token start. Base caps, call caps and daily quotas compose before any payload write. Reservations prevent parallel connections from independently spending the same quota. Unwritten bytes are refunded; consumed pacing tokens are conservative on write failures.

`proxy.rs` implements a real loopback-only SOCKS5 TCP relay with no packet interception. Production identity comes exclusively from the Windows adapter. There is no UI-selected fallback identity. Unknown or disabled applications cannot open a proxied connection. Rules are re-evaluated on each chunk, including established flows. Two bounded workers per flow handle each direction with 4 KiB buffers and finite socket read/write timeouts. Half-close allows request/response protocols to complete. At most 32 flow pairs are active; completed handles are reclaimed. Accept uses a nonblocking socket with a 250 ms parked wait; Stop unparks it without needing another socket. Throttled streams park for up to 20 ms. No thread spins waiting for a token.

OS hostname lookup runs on the bounded flow workers. The standard system resolver has no portable cancellation/timeout contract; a stalled resolver can delay Stop or shutdown. Connecting tries at most eight resolved addresses with a two-second timeout per address. Neither operation blocks the UI event handler. The relay accepts incoming connections only at `127.0.0.1`; it does not accept from the LAN. Application paths and local PIDs are attribution aids, not an adversarial security mechanism. Protecting traffic against malicious same-user code requires a different design.

`platform.rs` compiles actual Windows IP Helper bindings for TCP/UDP IPv4/IPv6 inventory and process identity. Aligned, bounded buffers, bounded size-race retries, length checks and short-lived read-only process handles contain the FFI boundary. No firewall, QoS, EStats-enabling, ETW session or service API is invoked.

`runtime.rs` owns bounded policy, updater and System TCP command queues. Settings I/O, connection inventory, proxy lifecycle, checkpoints, network checks and downloads run outside the UI. The System TCP worker blocks until an explicit Check/Apply/Pause; no launch probe or polling occurs. Immutable `Arc<View>` snapshots use short `try_lock` reads: pointer events do not clone thousands of endpoint strings. Idle control blocks on commands indefinitely; active proxy/monitor sampling wakes once per second. Only changed snapshots or completed commands request UI work. Inventory refresh is opt-in. Update networking has a 120-second total timeout and a ten-second connect timeout; streamed progress notifications are coalesced at 200 ms. No transfer or check runs every frame.

`window.rs` now owns a winit event loop and a CPU/GDI surface. `paint.rs` shares egui_software_backend rasterization between native frames and headless previews. Every useful raster starts from a clean backbuffer, avoiding old alpha-composited text surviving a layout change. Unchanged OS expose requests reuse the retained bitmap. `scheduling.rs` preserves finite repaint deadlines without `ControlFlow::Poll`; hidden/minimized windows skip layout/raster/present. A background result still reaches `App::poll` while hidden, so quit and restore do not depend on hidden paint events. Source and scheduler checks support this design; native idle/hidden frame behavior and presentation cost are unmeasured.

`tray.rs` provides a small native menu with Open, limiter start/pause, Call mode, Settings and Quit. It updates only when its displayed state changes. X hides when the tray exists; without it X requests shutdown. `instance.rs` uses one blocked named-event worker per active instance to reopen the same data-directory window on a second launch. The auto-reset event is session-local, uses default current-user security and carries only an Open request; it is not a privileged control interface. Native foreground activation and tray actions remain untested. The file lock still owns worker/data exclusivity.

`design.rs` defines shared palette, type and spacing roles. `ui.rs` separates application selection/rule editing, read-only Connections, System TCP (WinDivert) and Settings. Less frequent quotas/schedules remain discoverable in a named collapsible section. `preview.rs` constructs an isolated `App` with synthetic rules and no runtime workers, renders exactly two frames for each of seven fixed cases, writes PNGs and exits. It calls the same UI and rasterizer as normal operation. It cannot certify native input or performance. Optional native diagnostics collect bounded visibility segments and aggregate layout/raster/presentation time, written once on exit.

`storage.rs` uses a separate data directory, an exclusive instance lock, bounded JSON reads, synced temporary writes and same-directory replacement. Saves validate before persistence and activate only after persistence succeeds. Usage checkpointing is best effort every five seconds with a final checkpoint at normal shutdown. This cannot be a tamper-resistant or crash-exact quota ledger. Local clock changes can reset a daily quota. There is no historical traffic database or destination log.

`updater.rs` parses stable releases, verifies exact assets, streams bounded downloads, checks integrity and runs a separate executable helper only after user action. The helper acknowledges an open parent process handle before the UI exits, avoiding an exit/open race. After the parent exits it stages replacement beside the EXE, preserves a backup, atomically replaces and restarts. No shell interpreter, scheduled task, service, elevation or Codex dependency is used by the shipped updater.

`traffic.rs` converts saved enabled rules into a strict TCP-only policy, refusing unsupported features before IPC. GUI and WinDivert service share `backend/packet-control`, a version 3 pipe/backend identity distinct from the old WFP endpoint. Standard interactive users can read aggregate status; the broker impersonates the client to authorize administrator-only Apply/Pause. The client verifies the server PID against SCM before sending a policy. Framing/deadlines/cancellation and bounded channels isolate IPC from UI/capture work. The service starts paused, has no startup policy and no idle maintenance timer, and lives independently of the GUI.

`backend/packet-service` loads a protected absolute-path external WinDivert 2.2 x64 DLL only on authenticated Apply. Every driver open uses NO_INSTALL. FLOW events map new selected TCP tuples to executable identities; NETWORK packets enter bounded per-flow/direction FIFO queues with shared per-rule directional budgets. One event-driven worker owns stable overlapped receive buffers, checksum calculation, paced sends and bounded pause flushing. Unknown/unmatched/unsupported traffic passes unshaped. Pause releases queues without deliberately aborting TCP, but can cause bursts/reordering/loss. See [WinDivert design](WINDIVERT-DESIGN.md) for accounting, attribution races, limits and native checks still pending. No native packet operation has run in this session.

`backend/driver`, `backend/service` and `backend/control` retain the former experimental custom WFP v2 implementation. Its own kernel driver remains uncompiled without WDK, its old GUI path is removed, and its OOB abort/drain/unload requirements remain relevant only to old test VMs. See [legacy WFP design](WFP-DESIGN.md). Portable GUI updates do not replace either backend's service/runtime files.
